РЕДАКТОР КАРТ HELMET HEROES
==========================

Что это: автономный редактор карт (вкладка «Карта»). Позволяет рисовать тайлы,
ставить порталы, НПС-торговцев, банкоматы, спавны игрока/мобов и сохранять карту
в JSON (map_<номер>.json) — такой файл потом загружается на сервер.

КАК ЗАПУСТИТЬ
-------------
1) Нужен Node.js (https://nodejs.org, версия 18+).
2) Двойной клик по start-editor.cmd (в этой папке) ИЛИ по start-editor.cmd в корне
   проекта (legacy/) — он сам зайдёт в editor-dist и запустит сервер.
   Порт выбирается автоматически (8080; если занят — 8081..8090), браузер откроется сам.
   Вручную: в этой папке выполнить `node serve.mjs 8080` и открыть
   http://127.0.0.1:8080/editor в браузере.
3) Чтобы остановить — закрой окно "HH editor server".

ЧТО ВНУТРИ
----------
  index.html        сам редактор
  data/             каталоги (npcs.json — список торговцев; map_*.json — примеры карт)
  models/tiles/     нарезка тайлов по темам: <Set>/tiles.json + tile_N.png; index.json (список наборов)
                    mirrors.json — карта зеркальных id (mirrorId→baseId) для tools/hhrew-to-map.mjs
                    _backup_mirror/ — бэкап tiles.json до чистки зеркальных записей (2-й этап)
  models/swf/       атласы тайлов (GreenArea) и портал
  dynamic_content/  спрайт-листы и фоны
  serve.mjs         мини-сервер (раздаёт файлы + /editor)

КАК РАБОТАТЬ С КАРТОЙ (кратко)
------------------------------
  • Слой: «Земля 1» — по ней ходишь (твёрдая), склоны (9/10/21/22/33/54/55/67) клади сюда.
    «Земля 2/3» — односторонние платформы: снизу проходишь, спрыгнуть вниз — присесть+ВНИЗ.
    «Вода» — плавание. «Декор фона» и «Передний план» — без коллизии.
  • Палитра тайлов: выбираешь ЗОНУ и НАБОР, ниже — компактная сетка тайлов (наведение показывает
    увеличенное превью, «⇄» — зеркальный тайл, «★» — спец-тайлы: коин-бокс 31, баунс-пад 30).
    «⇄ Зеркало (H)» подставляет зеркальный id.
  • Инструменты: кисть/ластик/заливка/линия/прямоугольник/пипетка/выделение,
    портал, спавн врага, НПС-торговец, банкомат, спавн игрока.
  • Сохранение — кнопка «💾 Скачать JSON», имя файла map_<номер>.json.
  • Ширина/высота карты берутся из загруженного JSON (можно 36×13, 40×25 и т.д.).

ЧЕГО В РЕДАКТОРЕ НЕТ (и почему)
------------------------------
  Игра получает карту как 1 байт на клетку (сообщение geTiles: 6 слоёв), поэтому НЕ передаются
  в игру: поворот тайла, его размер (% клетки) и пиксельное смещение. Такие инструменты убраны
  из UI, чтобы не вводить в заблуждение (в JSON поля sizes/flags/offsets остаются — для
  обратной совместимости при чтении старых карт). Зеркало возможно и оставлено — оно делается
  ЗЕРКАЛЬНЫМ ID тайла (9↔10, 2↔4, …), а не флагом.
  Игровой клиент — Flash/SWF, внутри вкладки редактора его запустить нельзя, поэтому кнопка
  «▶ TEST» клиент НЕ открывает: она только проверяет карту на ошибки (см. ниже).

НОВОЕ (модернизация UI, см. MAP-EDITOR-PHASE1.md)

    внизу HUD: клетка, тайл, масштаб и глубина истории.
  • Панель «Слои» (слева): 👁 видимость, 🔒 замок, клик — активный слой, прозрачность, 🧹 очистить.
  • Правая панель: миникарта (клик — переход), Свойства объекта, Multi-tile brush, Проверка карты.
  • Multi-tile brush: инструмент «⬚ выделение» → рамка → «🎯 Взять выделение как кисть» → рисуй паттерном.
    Либо протяни область ПРЯМО В ПАЛИТРЕ — она станет кистью.
  • Объекты: инструмент «🎯 объекты»/«✥» — клик, Shift+клик (несколько), рамка по пустому месту,
    drag группой, стрелки — сдвиг (Shift ×5), Ctrl+C/V — копировать/вставить (вставка через
    превью: ЛКМ — вставить, Esc — отмена), Ctrl+D — дублировать, Delete — удалить.
    Кнопка «🎯» в строке списка объекта — выбрать его и центрировать на нём карту.
  • Горячие клавиши: B кисть, E ластик, F заливка, L линия, M перемещение, P пипетка,
    H зеркало, G сетка, Ctrl+S сохранить, Ctrl+C/V, Ctrl+D, Ctrl+Z/Y, стрелки (объекты), Delete, Esc.
  • Кисть-паттерн: «⇄ Зеркало паттерна» — зеркалит строку и меняет id на зеркальные (где есть).
  • Проверка карты: клик по сообщению с координатами (x,y) — переход к проблемной клетке.
  • TEST: кнопка «▶ TEST» проверяет ТЕКУЩУЮ карту на ошибки (validateMap + предупреждения,
    результат — в панели «Проверка карты»). Клиент НЕ запускается, ничего не сохраняется.
    Отдельная кнопка «⚙ Собрать Map.generated.cs» — сборка серверного кода (node tools/gen-map.mjs).
  • Undo/redo — дифференциальные: правки тайлов пишутся дельтами, полный снимок только
    для генерации/очистки слоя/вставки зоны.

5-Й ЭТАП: СТАТУС-БАР ПЕРЕСБОРКИ SWF (сохранение экипировки)
------------------------------------------------------------
  • ФИКС: сохранение позиций вещей/шлемов НЕ доходило до игры, потому что пересборка клиента
    вообще не запускалась. Причина — `spawn(..., { detached: true })` в serve.mjs: на Windows
    powershell.exe при detached:true молча ничего не делает (ни `tools/rebuild-client.log`,
    ни пересборки). Теперь spawn без detached — сборка реально идёт (~17 с).
  • «💾 Сохранить» на вкладке «Экипировка» для ПЕРСОНАЖА теперь всегда пересобирает SWF
    (правки в BodyAnimator.as попадают в игру только через сборку). Для ПИТОМЦА сборка не нужна —
    правки идут в живой `gamefs/dynamic_content/misc/pet_body_locations.xml` и видны после
    перезапуска клиента.
  • СТАТУС-БАР внизу вкладки: имя/размер/время SWF + значок валидности (✅/❌), полоса прогресса
    и ПРОЦЕНТ сборки, а также пояснение текущего шага. «Валиден» = SWF распаковывается и содержит
    базу ассетов `127.0.0.1:8080` (и не `github.io`).
  • Прогресс: `tools/rebuild-client-swf.ps1` пишет `tools/rebuild-progress.json`
    ({running, step, total, name, percent, ok, error}); проценты взвешены по 6 шагам
    (compile 15 · mxmlc 40 · extract 5 · stackfix 5 · set-abc 10 · deploy 25). Ошибка сборки
    ловится trap-ом, показывается в статус-баре, полный хвост — в подсказке (title).
  • Эндпоинт `/editor/api/equip-status` отдаёт `swfOk/swfCheck/percent/step/stepName/rebuilding/done/error`.


6-Й ЭТАП: ПУБЛИКАЦИЯ КЛИЕНТА В hht-client (GitHub Pages)
---------------------------------------------------------
  • Игра у игроков грузится с https://yuriifedorov01-cpu.github.io/hht-client/ — локальный
    `gamefs\MyGame.swf` им НЕ годится (он смотрит на 127.0.0.1:8080). Публикация собирает
    ОБЛАЧНЫЙ SWF и заливает его в репо hht-client (git-клон `deploy\hht-client`).
  • На вкладке «Экипировка» — кнопка «🌐 Опубликовать в hht-client» и галочка
    «публиковать в hht-client после сохранения» (по умолчанию включена, хранится в браузере).
    Сохранение персонажа = пересборка + публикация; сохранение питомца = запись XML + публикация.
  • Что делает публикация (`tools\publish-hht-client.ps1`, 11 шагов):
      1) подготовка исходников с публичными URL (`compile-client.ps1 -PublicBase .../hht-client/`);
      2) КОМПИЛЯЦИЯ MXMLC (`build-mxmlc.mjs`) — тем же конвейером, что и локальный клиент;
      3) извлечение ABC (`swf-extract-abc.mjs`);
      4) фикс кодогена Flex 4.16 (`abc-stackfix.mjs --fix`);
      5) вшивание ABC в `gamefs\MyGame.swf` -> `build\MyGame-cloud.fws`;
      6) ABC-патчи (НПС редактора, зонные гейты, ATM, меню) — как `deploy.ps1 map`;
      7) сжатие в CWS;
      8) ассеты: `gamefs\dynamic_content\` + `data\map_*.json` -> клон;
      9) `MyGame.swf` -> КОРЕНЬ клона (без `r\<gameId>\`);
      10) ПРОВЕРКА облачного SWF: нет `127.0.0.1:8080`, есть `github.io/hht-client/`, целы теги и DoABC;
      11) `git commit` + `push origin main`.
    ВАЖНО: облачный SWF собирается **mxmlc**, а НЕ ASC (`build\client.abc`). ASC-сборка падает
    при старте: `Error #1034: Type Coercion failed … playerio::PlayerIOError$cinit()` —
    это ошибка инициализации классов у ASC (см. комментарий в `compile-client.ps1`).
  • Если проверка не прошла — пуш НЕ делается (ошибка видна в статус-баре).
  • Вручную: `tools\publish-hht-client.ps1` (полный цикл), `-NoPush` (собрать, но не пушить),
    `-WithSwfPatches` (накатывать ABC-патчи), `-SkipCompile` (без перекомпиляции).
  • Игроки получают обновление за 1–2 минуты — Pages отдаёт статику, ZIP перекачивать не нужно.

8-Й ЭТАП: ДЕРЕВЬЯ (🌳) И РЫБЫ (🐟) — ОБЪЕКТЫ КАРТЫ
--------------------------------------------------
  • Деревья и рыбы — НЕ тайлы карты. В игре это объекты: `Tree.as` (рубится клавишей C, дропает
    бревно) и `Fish.as` (спавнятся в водоёмах). Спрайты лежат ВНУТРИ SWF (контейнер
    `TreeFishContainer`), внешних PNG нет — вынуты через FFDec (`-selectid`) скриптами
    `tools\_make-trees-set.mjs` и `tools\_make-fish-set.mjs` (перегенерировать можно в любой момент).
  • Наборы в палитре (отдельные зоны в списке «Зона»):
      «Trees» — 14 деревьев (pine tree, maple tree, …) → `models\tiles\Trees\`
      «Fish»  — 42 вида рыб (sliver, swarmer, puffer, …) → `models\tiles\Fish\`
    У наборов `kind` = `tree`/`fish` в `models\tiles\index.json`. ВЫБОР такого набора НЕ меняет
    тему карты (`themeMain`/`themeFg`) и не подмешивает зеркала/★ — это отдельный атлас.
  • ДЕРЕВЬЯ (размещение): выбери набор «Trees» → клик по спрайту = выбрать вид дерева →
    «✏ Кисть» ставит дерево на клетку (правый клик / «🧽 Ластик» — убрать). Одно дерево на клетку,
    повторный клик другим спрайтом меняет вид. Деревья рисуются поверх тайлов, спрайт прижат
    низом к клетке (как в игре: pivot = низ по центру).
  • РЫБЫ (виды карты): выбери набор «Fish» → клик по спрайту включает/выключает вид для этой карты.
    Кликать по карте НЕ нужно: сервер сам спавнит выбранные виды в связных водоёмах (до 15 на карту).
  • В JSON карты добавлены два поля (обратно совместимо, старые карты грузятся как есть):
      "trees": [[col, row, "pine tree"], ...]   — деревья по клеткам (имя = текстура в атласе игры)
      "fish":  ["puffer", "sliver", ...]        — виды рыб, которые спавнятся в воде этой карты
  • Undo/redo (Ctrl+Z / Ctrl+Y) и автосохранение покрывают деревья и рыб (через `objSnapshot`).
  • Под палитрой — сводка: для деревьев «поставлено N, выбрано <вид>» + «✕ убрать все деревья»,
    для рыб «виды: …» + «✕ очистить».

  ВАЖНО (что ещё НЕ сделано в игре — это следующий этап):
    – клиент пока НЕ спавнит деревья/рыб из карты (`new Tree(...)`/`new Fish(...)` не вызываются);
    – сервер пока ИГНОРИРУЕТ `treeHit` (`GameCode.cs: ignoredTypes.Add("treeHit")`) — дропа бревна нет;
    – респавн деревьев и коин-боксов (раз в ~15 мин или при перезаходе в зону) — на стороне сервера.
